# Nexus MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Before coding a library call, re-read the documentation cited in Phase 0. Do not invent Spring, Docker, or Next.js APIs.

**Goal:** Build a self-hosted control plane that discovers Docker projects on a VPS, shows live status/logs/metrics, deploys via allowlisted scripts, and records history, alerts, and audit.

**Architecture:** Hexagonal Spring Boot API (observed state from Docker Engine, desired state from `nexus.yml`, history in PostgreSQL) behind Nginx, with a Next.js App Router UI. Same-origin `/api` in production; Next rewrites in local dev. Realtime via MVC `SseEmitter`, not WebFlux.

**Tech Stack:** Java 21, Spring Boot 3.5.16, Spring Security 6.5.11, Flyway 11.7.2, docker-java 3.7.1 (httpclient5), PostgreSQL 16, Next.js 16.3.4, React, TypeScript, Tailwind, TanStack Query 5.102.8, Nginx, Docker Compose.

**Spec:** `NEXUS_VPS_DEPLOYMENT_SPEC.md` (source of product truth). This plan is the source of implementation truth for V1.

---

## Scope

### In (MVP = spec §51 + roadmap V0–V7)

Discover → observe → logs → errors → deploy → health → history → alerts → activity → rollback → auth → audit.

### Out (spec §48 / V8–V10)

Kubernetes, multi-server agent, GitHub OAuth/webhooks, Terraform, Elasticsearch, Kafka, Prometheus, Grafana, Redis, secret vault, marketplace, plugins, arbitrary terminal, remote file editor, incident grouping, metric history, auto-rollback.

### Lab target

The user already has a VPS running a 3-tier app (database + backend + frontend). That stack is the first managed project. Locally, `projects/lab/` is a tiny Compose stand-in so development does not depend on VPS access.

### SSE — Spring MVC `SseEmitter`

- Docs: https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-ann-async.html
- Return `SseEmitter` from `@GetMapping(produces = MediaType.TEXT_EVENT_STREAM_VALUE)`
- `new SseEmitter(0L)` for no timeout on log follow (or a long timeout + heartbeats)
- `emitter.send(SseEmitter.event().name("log").data(line))`
- `complete()` / `completeWithError(t)`
- On `IOException` from `send`: do **not** call complete
- Heartbeat comments so disconnects are detected
- Configure a real `AsyncTaskExecutor` (default is not production-suitable)

**Forbidden:** switching the server to WebFlux, `Flux<ServerSentEvent>` as the primary pattern.

### Spring Security 6.5.11

- Docs: https://docs.spring.io/spring-security/reference/6.5/servlet/configuration/java.html
- Docs: https://docs.spring.io/spring-security/reference/6.5/servlet/exploits/csrf.html
- `@Bean SecurityFilterChain` + `authorizeHttpRequests` + `requestMatchers`
- Cookie session (`JSESSIONID`). **Not** `SessionCreationPolicy.STATELESS`
- CSRF: `CookieCsrfTokenRepository.withHttpOnlyFalse()` + `SpaCsrfTokenRequestHandler` copied from the 6.5 CSRF docs
- Header `X-XSRF-TOKEN`, cookie `XSRF-TOKEN`
- `hasRole("ADMIN")` (authority becomes `ROLE_ADMIN`). Never `hasRole("ROLE_ADMIN")`
- JSON login is **custom** (`AuthenticationManager.authenticate(UsernamePasswordAuthenticationToken)`). There is no `jsonLogin()` on 6.5. Do not call `csrf.spa()` (that shortcut is not in 6.5 docs).

**Forbidden:** `WebSecurityConfigurerAdapter`, `antMatchers`, `authorizeRequests`.

### Process execution

- JDK 21 `ProcessBuilder` + argv list + `directory(workingDir)` + `redirectErrorStream(true)` + `inputReader(UTF_8)`
- Docs: https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/ProcessBuilder.html
- Executable path comes **only** from `nexus.yml` (allowlist). Never concatenate user input into a shell.

### YAML manifests

- Separate `YAMLMapper` bean (Jackson YAML). Bind onto a closed DTO.
- **Forbidden:** SnakeYAML Constructor of arbitrary types; replacing the primary JSON `ObjectMapper`.

## Decisions locked

| Decision | Choice | Why |
|---|---|---|
| Boot version | **3.5.16** not 4.x | Last OSS 3.5; Security 6.5 CSRF pattern is documented; Testcontainers 1.21.4 BOM |
| Build | Maven | `spring-boot-starter-parent` is the least-surprise path |
| Realtime | SSE / `SseEmitter` | Spec V1; no bidirectional need yet |
| Auth | Session cookie + CSRF cookie | SPA on same origin via Nginx |
| Docker access | Socket mount + identical-path bind of `/srv/projects` | Deploy scripts see host paths; no nested Docker |
| Schema | Flyway only, `ddl-auto: validate` | Spec + Boot guidance |
| Deploy | `ProcessBuilder` of manifest command | No arbitrary shell endpoint |
| Frontend | Next 16 App Router, no `src/` | Matches spec tree |
| Local API | Next rewrite keeps `/api` prefix | Spec endpoints are `/api/...` |
| Roles | `ADMIN`, `VIEWER` | Spec §31 |
| First user | Env bootstrap `NEXUS_ADMIN_USERNAME` / `NEXUS_ADMIN_PASSWORD` | Single admin V1 |
| Metrics | Docker stats + `/proc` + `Files.getFileStore` | No Prometheus |
| Logs storage | Docker only; Nexus stores fingerprints + deployment lines | Spec §15, §36 |

### Path identity rule (critical)

`nexus.yml` `workingDirectory` is a **host** path. The backend container must mount that path at the **same absolute path**. Example:

```yaml
volumes:
  - /var/run/docker.sock:/var/run/docker.sock
  - /srv/projects:/srv/projects
```

Locally, use `/home/ibetanzos/dev/nexus_project/projects/lab` mounted onto itself.

export async function api<T>(path: string, init: RequestInit = {}): Promise<T> {
  const csrf = document.cookie
    .split('; ')
    .find((c) => c.startsWith('XSRF-TOKEN='))
    ?.split('=')[1]

  const res = await fetch(path, {
    ...init,
    credentials: 'same-origin',
    headers: {
      'Content-Type': 'application/json',
      ...(csrf ? { 'X-XSRF-TOKEN': decodeURIComponent(csrf) } : {}),
      ...(init.headers ?? {}),
    },
  })
  if (!res.ok) {
    const body = await res.json().catch(() => null)
    throw new Error(body?.error?.code ?? res.statusText)
  }
  if (res.status === 204) return undefined as T
  return res.json() as Promise<T>
}

public final class DeploymentTransitions {
